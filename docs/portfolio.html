한 줄이 게임이 되기까지

명령 한 줄 · 생성마다 폴더 하나

  1. 기획서

    아이디어를 엔진이 만들 수 있는 범위 안의 기획서로 씁니다. 3D나 멀티플레이 같은 범위 밖 요청은 줄인 내용을 기획서에 적어 둡니다.

  2. 그림

    Codex의 이미지 생성으로 캐릭터 그림 한 장을 만들고, 분홍 배경을 지워 게임에서 바로 쓰는 그림으로 바꿉니다.

  3. 게임 코드

    브라우저 하나로 도는 한 화면짜리 게임을 만듭니다. 기획서·그림·게임·검사 결과가 생성마다 폴더 하나에 남습니다.

  4. 플레이 검사

    화면 없는 브라우저에서 키를 눌러 움직임, 점수 변화, 승패 도달을 확인합니다. 하나라도 빠지면 그 생성은 실패로 멈춥니다.

통과 기준을 바꾼 과정

2026년 6월 29일 · 생성 6회

  1. 문제

    처음 세 번은 게임이 Canvas를 쓰는지, 만든 그림을 그리는지, 화면이 찍히는지까지만 확인했습니다. 캐릭터가 움직이지 않는 게임도 이 기준은 넘을 수 있었습니다.

    화면 찍힘 = 통과
  2. 판단

    게임 코드마다 검사용 조작 통로와 상태 읽기 창을 꼭 넣게 했습니다. 검사기는 이 통로로 키를 누르고, 점수와 위치와 승패를 읽습니다.

  3. 검증

    검사기 자체도 시험했습니다. 일부러 멈춰 둔 가짜 게임을 매번 같이 돌리고, 가짜가 통과하면 검사기가 못 거른 것으로 보고 생성 전체를 멈추게 했습니다.

  4. 결과

    뒤 세 번은 실제 게임 3개가 모두 통과했고 멈춘 가짜 3개는 모두 걸렸습니다. 승리까지 닿은 게임은 Moon Fern Dash 하나이고, 나머지 둘은 시간 초과 패배까지 확인했습니다.

Crystal Fox Dash에서 Moon Fern Dash로

Crystal Fox Dash를 끝내자 위에서 내려다보는 2D 화면, 대시, 수집 점수, 제한 시간으로 된 게임 뼈대가 재사용 후보로 저장됐습니다. 바로 다음 Moon Fern Dash가 이 뼈대를 받아 만들어졌고, 사용 횟수가 1에서 2로 올라갔습니다.

  • 서로 다른 생성 5번에 쓰이면 안정 단계로 바뀜
  • 같은 오류가 3번 나오면 미리 막는 규칙 후보로 올림
  • 규칙 후보는 사람이 승인해야 다음 생성에 적용

두 게임 모두 파이프라인이 만든 그대로 브라우저에서 해 볼 수 있습니다. 방향키나 WASD로 움직이고 Space로 대시합니다.

할 수 있는 것

한 화면 · 캐릭터 하나 · 승패 하나

한 화면 Canvas, 그림 한 장, 키보드 입력, 클릭 재시작, 위에서 내려다보는 2D 이동, 대시, 단순 충돌, 점수·시간·승패, 기본 화면 표시 등 14가지입니다.

못 하는 것

3D부터 모바일 포장까지

3D, 네트워크 멀티플레이, 서버 저장, 넓은 월드, 복잡한 물리, 여러 장면 애니메이션, 타일맵, 셰이더, 소리, 인벤토리·대화·퀘스트, AI 캐릭터, 모바일 앱 포장 12가지입니다.

플레이 검사가 하는 일조작 통로 · 상태 읽기 · 가짜 게임 시험
코드 검사게임 파일에 Canvas, 만든 그림의 경로, 그림 그리기, 상태 읽기 창, 조작 통로가 모두 있는지 먼저 봅니다. 하나라도 없으면 바로 실패로 멈춥니다.
움직임 시험오른쪽·아래·대시 키를 12초 동안 넣고 위치와 점수, 승리 여부를 읽습니다.
패배 시험15초 동안 시간을 흘려 패배 화면에 닿는지 봅니다.
가짜 게임 시험아무것도 안 움직이는 가짜 게임을 같은 검사에 넣습니다. 가짜가 통과하면 검사기를 믿을 수 없으므로 생성 전체를 멈춥니다.
결과 파일각 생성 폴더의 검사 결과 파일에 항목별 통과 여부와 시험 중 읽은 상태가 남습니다.
